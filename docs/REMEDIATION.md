## ⚠ ESCALATED: reports — PyYAML CVE-2020-14343

**Status:** Rolled back. Needs human decision before the secure version can be applied.

**Why the secure bump breaks tests (rule 05):**  
`services/reports/tests/test_report_loader.py:11` uses a YAML fixture with a `!!python/object:report_loader.ReportSpec` tag. PyYAML 6.0 `FullLoader` rejects this tag with `yaml.constructor.ConstructorError` — the only loader that accepts it is `yaml.UnsafeLoader`, which is explicitly forbidden by rule 05 §1 as an unsafe option.

**Break output (PyYAML 6.0, before rollback):**
```
FAILED tests/test_report_loader.py::test_load_report_spec
yaml.constructor.ConstructorError: could not determine a constructor for the tag
  'tag:yaml.org,2002:python/object:report_loader.ReportSpec'
```

**KEV & Reachability:**
- KEV status: — Not listed
- Reachability: ⚠ **Reachable** — `services/reports/report_loader.py:25` — `yaml.load(f, Loader=yaml.FullLoader)` reads a caller-supplied file path; FullLoader is vulnerable to `!!python/object/apply` RCE on attacker-controlled YAML.

**Options:**
1. **Migrate** — Rewrite report spec files to plain-dict YAML (remove `!!python/object` tag); update `report_loader.py` to use `yaml.safe_load`; update `tests/test_report_loader.py` to assert plain-dict output. This closes the CVE cleanly.
2. **Accept risk with sign-off** — Restrict YAML input to trusted internal paths only; document compensating control; schedule migration. Requires explicit security team sign-off.
3. **Pin and isolate** — Keep PyYAML 5.3.1 in a sandboxed environment, monitor for active exploitation, schedule a migration sprint.

**Recommended:** Option 1 (Migrate). The `!!python/object` pattern is the root cause of the vulnerability; removing it both fixes the CVE and eliminates the class of risk.
